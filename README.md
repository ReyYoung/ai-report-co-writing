# ai-report-co-writing

[English](README_EN.md) | 中文

一个让 AI 和你一起编写长篇 Word 文档的 Agent Skill，适用于技术标、可研报告、解决方案、汇报材料。它给 AI 定了一套从招标文件到定稿的做法：先拆需求、出目录，你确认后再分章编写、评审、合稿出图，之后按同一套规矩做多轮修订。全程守住三点：内容有依据，全文前后一致，你自己的修改不会被覆盖。

## 这是什么

一份 `SKILL.md`，给支持 Skill 的 AI Agent 使用。它不是写作模板，而是一套工作方法。

它来自一次真实的技术标编制：300 多页，从需求分析做起，前后改了 18 版。这个 Skill 把这个过程里用过的做法和踩过的坑，整理成了 AI 每一步都要遵守的规矩。

## 解决什么问题

| 常见问题 | Skill 里的做法 |
|---|---|
| 招标文件几十页，需求和强制项漏看、漏答 | 先逐条拆成功能需求、非功能需求、强制项、信息缺口四张表；目录做覆盖度统计，每条需求都有落点 |
| AI 一上来就写正文，结构不对只能推倒重来 | 先出带编写指引的目录，你确认后才分章写 |
| 初稿写完，分不清哪些要自己补、哪些可以交给 AI | 初稿评审后出整改清单，分成“人工补充”和“AI 修改”两张，标明优先级和依赖关系 |
| 你在 Word/WPS 里改过的内容，被 AI 的下一版覆盖 | 每次动手前核对文件的 md5 和修改时间，以你的最新文件为底稿，在你的修改之上继续改 |
| 工期、人数、版本号改了一处，表格和插图里漏了十几处 | 维护一张口径表；口径一变，对正文、表格、插图做全文扫描，改完再扫一遍确认没有残留 |
| 没有依据的资质、业绩、证书被编出来 | 事实只来自招标文件和你提供的材料，没有依据的一律写成【待补充：……】并标红 |
| 篇幅不够时套模板凑页数 | 只在原有功能点上深化，不另起模板化小节 |
| 换软件保存后页数变化、分页全乱 | 直接修改文档 XML 并保留原格式，不用 LibreOffice 保存你的文件 |
| 标题、表格、插图各写各的 | 版式、表格、插图有统一的默认规范，通过样式统一设置 |
| 大改之后说不清改了什么 | 每版附修订记录、标黄对比版和待确认清单 |

## 包含的内容

`SKILL.md` 分十个部分：

1. **编制原则**：事实有依据、结论先行、不新增承诺、口径表、按招标条款组织。
2. **编制流程**：需求分析四张表、目录与编写指引、分章编制、初稿评审与分工清单、合稿与出图、评分对照与招标变化。
3. **修订流程**：先出方案再改、以最新文件为底稿、版本管理、写回校验、全文扫描、简短的交付说明。
4. **版式规范**：页面、正文、各级标题、题注、目录的默认值。
5. **表格制作规范**：样式、列宽与对齐、内容与位置、制作方法。
6. **插图绘制规范**：配色、字号、分层架构图、进度图、甘特图、流程图的画法，以及检查和归档方式。
7. **Word 文档的安全编辑**：怎样改才不破坏原文件的格式和分页。
8. **逐条应答与偏离表**：招标条款逐条应答的写法和校验。
9. **扩写与页数**：篇幅不够时怎么扩，页数怎么调。
10. **交付物**：修订记录、对比版、待确认清单。

## 适用范围

适用于几十到几百页、从零编制并需要多轮修订的 Word 文档，例如投标技术标、可研报告、解决方案、项目汇报材料。

不太适用的情况：一两页的短文、一次成稿不再修改的文档、非 Word 格式的文档。

## 快速开始

**1. 安装**

**一句话安装**：在 Agent 对话框里发送：

```text
请从 https://github.com/ReyYoung/ai-report-co-writing 安装 Skill，名称为 ai-report-co-writing；安装完成后确认能读到 SKILL.md，并告诉我安装路径。
```

**手动安装**：把本仓库中的 `ai-report-co-writing` 文件夹（内含 `SKILL.md`）放到你所用 Agent 的 skills 目录，或按该 Agent 的方式导入。

```bash
git clone https://github.com/ReyYoung/ai-report-co-writing.git
# 以 Claude Code 为例，个人 Skill 目录为 ~/.claude/skills/
cp -r ai-report-co-writing ~/.claude/skills/
```

其他 Agent 的安装方式请以各自的官方文档为准。

**2. 准备材料**

- 招标文件或需求文件（建议用脱敏版）
- 你已有的方案资料、产品资料
- 文档模板（如果招标方或公司有要求）

**3. 开始使用**

```text
使用 ai-report-co-writing，根据这份招标文件编制技术标。
先做需求分析，再给我带编写指引的目录，我确认后再分章写。
```

修订时：

```text
项目周期从 8 个月改成 6 个月。先列出哪些地方需要改、改成什么，我确认后再改。
```

## 运行环境

- 一个能读写本地文件、能运行 Python 的 AI Agent。
- Python 库：`python-docx`、`lxml`。
- Playwright（Chromium）：把 SVG 插图渲染成 PNG。
- LibreOffice（可选）：只用来转 PDF 预览和核对页数，不用来保存文档。没有也能用，页数按版式参数估算，以你在 Word 或 WPS 里看到的为准。

已在 Claude、WorkBuddy、千问办公中实测可用。其他支持 Skill 的 Agent 理论上也可以使用，但没有逐一验证。

## 默认规范与自定义

版式部分的默认值是中文正式文档的常用写法（正文宋体小四、标题黑体、1.5 倍行距，插图用一套蓝色系）。招标文件、公司模板或你自己另有要求时，以它们为准。你也可以直接修改 `SKILL.md` 里的默认值。

Skill 中关于 WPS、样式编号等细节，来自中文办公环境下的实际经验，在其他环境下可按需调整。

## 使用建议

**分工**：人负责判断，AI 负责执行。目录和方案怎么定、口径怎么定、产品能不能做到、每一句承诺是否成立，由人决定；拆需求出目录、分章写初稿、改稿排版画图、全文一致性检查、出修订记录和对比版，交给 AI。

**几个确认点**：目录出来后、分章初稿和两张清单交出后、插图样张出来后、每一轮修订动手前，它都会停下来等你确认。想跳过时明确告诉它，例如“不必确认目录，直接写”。

**数据安全**：给 AI 的招标文件用脱敏版；资质、业绩、证书、人员等敏感内容不交给 AI，由你手动补充到【待补充】的位置。

**每版交付看三样**：修订记录（改了什么）、对比版（改在哪）、待确认清单（需要你拍板什么）。

**先更新目录**：文档里的目录页码预留为空。在 Word 或 WPS 里打开后，右键目录，选“更新域”，再选“更新整个目录”，页码才会出现。

## 它不能做什么

- 不能替你中标。
- 不能替你判断产品是否具备某项能力，正文里写成功能的内容需要你逐项确认。
- 【待补充】的内容需要人来填。
